The artifact both engines must produce (a typed User struct + Validate method) MUST exercise:

1. Conditional imports (the dimension Jennifer wins on, templates struggle with):
   - "time" — required when User has any datetime attribute (e.g., a `Created time.Time` field).
   - "regexp" — required when User has a string attribute with a pattern constraint (e.g., username regex check in Validate()).
   - "errors" or "fmt" — required when Validate() returns errors.

2. Nested types: a slice of complex sub-attributes (e.g., `Emails []UserEmail` where `UserEmail` is its own struct with `Value`, `Type`, `Primary`).

3. Branching validation in Validate():
   - Required check: `if u.UserName == "" { return ... }`
   - canonicalValues check: `if u.Title != "" && !slices.Contains([]string{"Mr","Mrs","Ms","Dr"}, u.Title) { return ... }` — this exercises the "slices" import in 1.25+.
   - Multi-valued primary cardinality: count how many `u.Emails[i].Primary == true`; error if > 1.
   - String pattern (regexp.MustCompile in Validate()) exercises "regexp" conditional.

The spike fixture data (the `userData` struct in main.go) toggles which features are emitted; both engines receive the SAME fixture and produce the same Go output.

Module isolation:
- spike/template/go.mod  — `module github.com/imulab/go-scim/spike/template`, `go 1.25`, NO third-party deps.
- spike/jennifer/go.mod  — `module github.com/imulab/go-scim/spike/jennifer`, `go 1.25`, requires `github.com/dave/jennifer v1.7.1`.
- Neither module is added to the root go.work `use` directive (per CONTEXT.md "Both implementations live in spike/ (excluded from go.work use)").
- Built and run via `cd spike/template && GOWORK=off go run .` and `cd spike/jennifer && GOWORK=off go run .`.

Reference snippets (verbatim from 00-RESEARCH.md Code Examples 3 and 4):
- text/template skeleton uses `text/template` (NOT html/template — Pitfall 4 in 00-RESEARCH.md), `bytes.Buffer`, then `go/format.Source(buf.Bytes())`. Conditional imports are in template control blocks: `{{- if .HasTime }}...{{- end }}`.
- jennifer skeleton uses `jen.NewFile("domain")`, `f.HeaderComment("Code generated by spike/jennifer. DO NOT EDIT.")`, `jen.Qual("time", "Time")` for typed-import qualification, `f.Save("output/user_gen.go")` (which calls go/format internally).

Scoring criteria (verbatim from CONTEXT.md `<decisions>` "Emission-engine spike"):
1. Import management — does the engine auto-track imports across conditional emission paths?
2. Source readability — can a contributor reading the emitter understand what it produces?
3. Diff stability — two regen runs produce byte-identical Go (REQ-GEN-06 dry run).
4. Mixed-output compatibility — Go-emission winner does not preclude using text/template for non-Go artifacts (SQL/Makefile/README) per STACK.md.

Both implementations stay in-repo permanently — the comparison is the audit trail. Do NOT `git rm` the loser after the decision lands.

Header marker (REQ-GEN-03): every generated file's first non-blank line is `// Code generated by spike/<engine>. DO NOT EDIT.`
File naming (REQ-GEN-04): output is `user_gen.go` (the `*_gen.go` convention).
