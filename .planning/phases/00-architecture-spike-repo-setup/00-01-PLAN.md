  <action>
Create `CONTRIBUTING.md` at the repo root using the hard-prohibition tone (mirroring PITFALLS.md structure: prohibition + reason + warning signs). The document MUST contain at minimum:

1. A short "Why this file exists" preamble (2-3 sentences) explaining that this project is a rewrite of a legacy SCIM implementation that collapsed under three architectural pitfalls, and the rules below exist to prevent regression.

2. Three numbered, named sections — one per rule. Each section MUST follow this template:
   - Heading: `## Rule N: <short name>`
   - Single-sentence prohibition starting with "You MUST NOT..."
   - "Why" subsection citing the concrete legacy artifact paths and the failure mode that resulted
   - "Warning signs" subsection listing 3-5 code shapes that mean a contributor is sliding into the relapse
   - "If you think you need this" escape valve subsection (e.g., "open an issue, do not bypass")

   Rule 1: No generic Property / tree models in `rt` or generated code
   - Cite: `.legacy/pkg/v2/prop/property.go` (Property interface), `.legacy/pkg/v2/prop/subscriber.go` (ExclusivePrimarySubscriber, lines 106-180), `.legacy/pkg/v2/prop/navigator.go`
   - Warning signs include: any `interface { Path(...) ... }`, any `Property` interface declaration, any subscriber/observer pattern over a generic tree, any `NewString` / `NewComplex` factory style.

   Rule 2: No runtime schema interpretation — discovery payloads are //go:embed only
   - Cite: `.legacy/cmd/internal/args/scim.go`, `.legacy/asset/schema/`
   - Warning signs include: `os.ReadFile` with anything that smells like a schema path, JSON parsing of schema files at startup, any code that takes a `--schemas-dir` style flag in `rt`/generated code.

   Rule 3: No IdP-specific accommodations (Entra, Okta, Azure AD, etc.) in v1
   - Cite: PITFALLS.md Pitfall 3 (no concrete legacy artifact — this rule is preventive).
   - Warning signs include: vendor names appearing in source files, conditional logic keyed on `User-Agent` or vendor headers, "tolerance" or "lenient" parsing flags, special-cased capitalization aliasing.

3. A short "How this is enforced" section listing the four levers (PR template, CODEOWNERS, lefthook pre-commit + commit-msg, CI mirror) with one-line descriptions and links to their config files.

4. A short "If you absolutely need to break a rule" section pointing to opening an issue and citing PROJECT.md "Out of Scope" — the rules can be amended via project decision, not bypassed via PR.

Tone: hard prohibition, second-person ("You MUST NOT..."), no hedging, citable in PR comments. Follow the user's preference in CONTEXT.md `<specifics>`: "Hard prohibition tone preferred over principles — direct citability in PR comments."

Do NOT add an exhaustive table of contents, badges, or markdown decoration. Surgical content only.

<task type="auto">
  <name>Task 3: Configure lefthook pre-commit and commit-msg hooks</name>
  <files>lefthook.yml</files>
  <action>
Create `lefthook.yml` at repo root configuring three commands. The full content MUST be lifted from 00-RESEARCH.md Code Example 6 with these exact regex patterns (verbatim — these match the CI grep gate in Plan 02 for parity):

`pre-commit:`
1. `no-go-work` — refuses to stage `go.work` or `go.work.sum` (regex: `(^|/)go\.work(\.sum)?$`). Run with `parallel: true`.
2. `forbidden-symbols-source` — globs `{gen,rt}/**/*.go`; greps staged files for any of: `os\.ReadFile.*[Ss]chema`, `interface\s*\{\s*Path\(`, `Property\s+interface`. Exits 1 with message pointing to CONTRIBUTING.md.
3. `forbidden-vendor-names-source` — globs `{gen,rt}/**/*.go`; greps staged files (case-insensitive) for `Entra|Okta|Azure\s*AD|AzureAD`. Exits 1 with message pointing to CONTRIBUTING.md §3.

`commit-msg:`
1. `vendor-names` — greps the commit message file (`{1}`) case-insensitive for `Entra|Okta|Azure\s*AD|AzureAD`. Exits 1 with message pointing to CONTRIBUTING.md §3.

Use `lefthook` as the binary (NOT `pre-commit` Python or `husky` Node — per 00-RESEARCH.md Standard Stack the choice is lefthook because it's a single Go binary and the project is Go-only).

After writing the file, attempt local install: run `lefthook install 2>&1 || echo "lefthook not on PATH (developer machine setup required; CI mirror in Plan 02 is the security boundary)"`. The hook install is best-effort; absence of the binary is not a plan failure because per Pitfall 4 in 00-RESEARCH.md the CI mirror is what actually gates merges.

Do NOT add a `pre-push` hook, `prepare-commit-msg` hook, or any hook that invokes `go test` / `go build` / `go vet` — those slow down commits and add no value at Phase 0 (no source code yet to test). Surgical: the four hook commands listed above and nothing else.

Verify the YAML is parseable (Go's `yaml` toolchain is not required; use `python3 -c 'import yaml,sys; yaml.safe_load(open(sys.argv[1]))' lefthook.yml` if Python is available, otherwise read the file back and confirm the four commands exist by name).
